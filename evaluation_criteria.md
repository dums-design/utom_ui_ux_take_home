# Evaluation Criteria

## How Your Work Will Be Assessed

This take-home assignment is evaluated across **5 key dimensions**. Each dimension is equally important and contributes 20% to your final score.

---

## 1. AI Leverage & Efficiency (20%)

**What we're looking for:**
- Evidence of strategic AI tool usage
- Efficient workflow that maximizes the 3-hour time limit
- Smart use of AI for scaffolding while adding human refinement
- Ability to generate and rapidly iterate on designs

**Scoring rubric:**

| Score | Description |
|-------|-------------|
| **Excellent (18-20)** | Clear evidence of sophisticated AI usage; outputs are heavily customized and refined; efficient time management resulted in polished work |
| **Good (15-17)** | Used AI effectively; reasonable customization; good time management |
| **Satisfactory (12-14)** | Basic AI usage evident; some customization; acceptable time management |
| **Needs Improvement (0-11)** | Minimal AI usage evident, or over-reliance on generic AI outputs without customization |

**What demonstrates excellence:**
- Your README shows thoughtful AI prompting strategy
- Designs show clear customization beyond AI defaults
- You completed high-quality work within 3 hours
- Evidence of iterative refinement with AI assistance

---

## 2. Design System Adherence (20%)

**What we're looking for:**
- Consistent use of the provided design system (colors, typography, spacing)
- Proper implementation of CSS variables from `design_guide.html`
- Visual consistency across all 5 screens
- Professional application of the CineMatch brand aesthetic

**Scoring rubric:**

| Score | Description |
|-------|-------------|
| **Excellent (18-20)** | Perfect adherence to design system; consistent styling across all pages; proper use of all design tokens (colors, spacing, typography) |
| **Good (15-17)** | Strong adherence with minor inconsistencies; mostly correct use of design system |
| **Satisfactory (12-14)** | Moderate adherence; some custom styles that deviate from design system |
| **Needs Improvement (0-11)** | Poor adherence; random colors/fonts; significant deviations from design guide |

**What demonstrates excellence:**
- All colors use CSS variables from design guide
- Typography hierarchy matches the design system
- Spacing and layout follow established patterns
- Components look like they're part of a unified product

---

## 3. Visual Design & Polish (20%)

**What we're looking for:**
- Modern, clean aesthetic that aligns with current design trends
- Attention to detail (alignment, spacing, visual hierarchy)
- Thoughtful use of white space and layout
- Professional-looking UI that you'd be proud to show a stakeholder

**Scoring rubric:**

| Score | Description |
|-------|-------------|
| **Excellent (18-20)** | Beautiful, modern design; exceptional attention to detail; clear visual hierarchy; professional polish throughout |
| **Good (15-17)** | Attractive design; good attention to detail; clear hierarchy; mostly polished |
| **Satisfactory (12-14)** | Acceptable design; reasonable attention to detail; some areas need polish |
| **Needs Improvement (0-11)** | Poor visual design; lack of hierarchy; looks unfinished or unprofessional |

**What demonstrates excellence:**
- Designs feel modern and current (2024/2025 aesthetics)
- Strong visual hierarchy guides the eye naturally
- Thoughtful use of images, icons, and visual elements
- Every screen feels intentionally designed, not thrown together

---

## 4. Interactions & User Experience (20%)

**What we're looking for:**
- Smooth transitions and animations
- Intuitive navigation between pages
- Thoughtful micro-interactions (hovers, clicks, focus states)
- Clear user flows that make sense

**Scoring rubric:**

| Score | Description |
|-------|-------------|
| **Excellent (18-20)** | Delightful interactions throughout; smooth animations; excellent UX; everything works as expected; intuitive navigation |
| **Good (15-17)** | Good interactions; most animations work well; solid UX; clear navigation |
| **Satisfactory (12-14)** | Basic interactions present; some animations; acceptable UX; navigation works |
| **Needs Improvement (0-11)** | Minimal interactions; broken navigation; poor UX; abrupt transitions |

**What demonstrates excellence:**
- Hover states on all interactive elements
- Smooth transitions between states (fade in/out, slide, etc.)
- Modal windows open/close elegantly
- Navigation feels natural and intuitive
- Loading states or skeleton screens (bonus!)
- Filter interactions that feel responsive (even if simulated)

---

## 5. Technical Implementation (20%)

**What we're looking for:**
- Clean, well-structured HTML/CSS/JS
- Proper semantic HTML and accessibility basics

**Scoring rubric:**

| Score | Description |
|-------|-------------|
| **Excellent (18-20)** | Clean, semantic code; fully responsive; no bugs; accessible; works flawlessly across browsers |
| **Good (15-17)** | Good code quality; mostly responsive; minor bugs; generally accessible |
| **Satisfactory (12-14)** | Acceptable code; basic responsiveness; some bugs; limited accessibility |
| **Needs Improvement (0-11)** | Poor code quality; not responsive; multiple bugs; not accessible |

**What demonstrates excellence:**
- Valid, semantic HTML5
- Modern CSS (Grid, Flexbox, CSS Variables)
- Responsive design (desktop and laptop sizes minimum)
- No console errors in browser DevTools
- Accessibility basics (alt text, semantic elements, keyboard navigation)
- Cross-browser compatibility (Chrome, Firefox, Safari, Edge)

## Common Pitfalls to Avoid

### ⚠️ Design Pitfalls:
- Ignoring the design guide and using random colors/fonts
- Inconsistent styling across pages
- Poor visual hierarchy
- Cluttered layouts with no white space
- Using low-quality or improperly sized images

### ⚠️ Technical Pitfalls:
- Console errors
- Abrupt transitions (no animations)
- Generic AI outputs without customization
- Missing hover states

### ⚠️ Process Pitfalls:
- Not reading all documentation before starting
- Spending too long on one page
- Over-engineering solutions
- Skipping the QA phase
- Not documenting your approach in README
